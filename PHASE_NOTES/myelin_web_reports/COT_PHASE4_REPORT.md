# What was built
* **Menu → Modules → COT** is a real page (no reserved page remains). Layout follows the supplied reference: title and "Simulation mode | All timestamps in IST | No real monitoring", **GET REPORT** at the top, **four boxes in the requested order — Reminders displayed · Yes responses · No responses · Yes : No ratio** (`0 : 0` + "No responses recorded" when empty; percentages when answers exist), **Reminder session status** banner (Active Session / COT paused — covered by <organ> / No active session, next check-in countdown, current activity), **Session journey map** with the check-in telemetry panel on its **right side**, **Recent COT sessions**, **Most used activity categories** (by time spent), a short "About this simulation" card, and the simulation controls.
* **Popup (gentle, non-blocking):** a small card, not a modal — no overlay, page stays usable. Asks exactly **"Is it related to your work?"** with **YES** and **NO** (plus a quiet NOT NOW). YES → **GREAT — ENJOY YOUR WORK.** NO → **COME BACK SOON — YOU HAVE A LOT OF WORK TO DO.** No escalation, no forced navigation. Shown while the COT page is open.
* **Schedule:** first check-in after 10:00 of eligible simulated activity, then 20:00, 30:00 … every 10 minutes; each is recorded at its exact instant on the deterministic simulation clock (+30 SEC / +1 MIN / +10 MIN / ADVANCE TO NEXT CHECK-IN — no real waiting). Only displayed popups are counted.
* **Pause / resume:** entering an activity covered by SINE, MINE, SECANT, COSINE, FINE or STORE pauses COT — no popup, countdown frozen, remaining time preserved, nothing accumulates. Resuming continues the same sequence from the saved countdown; with **less than 60 s left, one full minute** passes before the pending popup (9:30 → pause → resume → popup after 1 minute; the next one stays on the original 20:00 mark). Exactly 60 s left needs no grace.
* **Session reset:** only the **explicitly designated focus app** ends the session (kept in the history, counters reset). A new session starts only with the next eligible activity. No app (e.g. ResearchGate) is a reset destination unless designated; in the Instagram → ResearchGate example ResearchGate is simply the resumed eligible activity. With no focus app designated, nothing resets.
* **Journey map:** built only from recorded events (session started, activity entered, COT paused / resumed, check-in with YES / NO / unanswered / awaiting, session ended / reset), icons, coloured nodes, connectors with elapsed time, IST timestamps. A session selector with older / newer arrows controls the map, the four boxes, the telemetry and the categories; clicking a recent-session row selects it; VIEW ALL pages the history.
* **Check-in telemetry:** historical simulated activity records (activity, category, entry IST, time spent, COT response, exit / pause event) — explicitly *not* a live feed and no real application or browser detection.
* **GET REPORT:** preview + downloadable TXT for the selected session (id and IST times, four metrics, recorded responses, chronological journey, telemetry), headed "SIMULATION EVIDENCE — NOT REAL DEVICE OR BROWSER MONITORING". YES is described as a self-reported statement, never verified focus or recovery. No PDF, no database.
